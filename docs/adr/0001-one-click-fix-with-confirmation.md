# 一键修复：从“不做自动修复”转向“逐处确认后写入”

Status: accepted

第一阶段明确移除了 `fixCode` 和自动修复能力；第二阶段重新引入代码修改，但以结构化修复补丁 + 编辑器内逐处确认 + “全部接受 / 全部拒绝 / 撤销全部”的方式落地，且补丁由 ErrAnalyst 自有 LLM 管线生成，不依赖 Continue 扩展。选择自有管线是因为 Continue 生产环境未暴露可编程的补丁生成/应用 API，逐处确认、计数和侧边栏汇总必须由 ErrAnalyst 自己实现；确认后才写入文件，规避“自动修复”无确认写盘的风险。

Consequences: 任何后续重构必须保留“AI 只能修改已出现在 Source Context 中的文件”和“展示前、应用前双重校验”两条护栏；修复补丁不作为缓存内容，始终基于当前文件内容现场生成。自 ADR-0002 起，从“错误分析对话”生成的补丁将白名单扩展为“对话上下文”（自动加载 + 用户新增），同时仍保留双重校验与不缓存原则。
