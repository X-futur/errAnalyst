# 核心报错术语与中文翻译：从“术语对照表 + 保留英文”转向“核心术语胶囊 + 纯中文翻译”

Status: accepted

侧边栏“中文翻译”与“关键词胶囊”之前按“中英术语对照表”设计：Prompt 要求翻译中用 `{{keyword}}` 包裹英文术语，`keywords` 没有收录边界。实际效果是胶囊混入 `embedding`、`status code` 这类普通英文词，且翻译保留英文原文，中文表达不自然。

本决策把两处行为重新定义：

1. 胶囊只展示“核心报错术语”，即最能指认本报错主题的词或短语。专有名词/标识符（异常类型、类名、函数名、库/API/框架/模型名）出现在报错中即收录；领域概念词（如 `embedding`）仅在直接参与根因且中文解释有增量价值时收录；普通英文词（如 `status code`）不收录。每报错最多 3 个，可以为空。
2. 中文翻译必须自然、专业、流畅：可翻译的技术概念必须译成中文（`embedding` → 向量嵌入）；无法翻译的专有名词保留原文并紧跟括号简释（如 `OptionalError（可选值错误）`）。该规则只约束“中文翻译”字段，错误分析与修复建议保持原有“中文叙述 + 必要时保留英文专名”的风格。

Considered Options:

- 继续使用通用术语对照表，仅减少数量（被否：数量不是质量问题，收录边界才是）。
- 完全零英文翻译，专名也全部中文化（被否：异常类名、模型名等没有可靠译名，强制替换会失真）。
- 依赖模型自觉“宁缺毋滥”（被否：无机械校验时结果不可预期）。
- 由模型二次过滤候选术语（延后：成本高，先由 Prompt 约束 + 扩展端机械校验承担）。

Consequences:

- `keywords` 字段语义从“中英术语对照表”变为“核心报错术语”，任何后续重构必须保留 0-3 上限、来源可追溯（术语必须能对应原始报错文本）与通用词排除三条护栏。
- `translation` 不再使用 `{{keyword}}` 标记，渲染端无需再做标记高亮；英文只以“专名 + 括号简释”形式出现。
- 本地缓存格式升级，旧格式缓存将被清空；重新分析后按新格式写入。
- Prompt 与扩展端校验各自负责一部分：语义判断由模型完成，数量/空值/重复/来源检查由扩展端完成。
