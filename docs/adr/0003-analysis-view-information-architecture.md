# 错误分析视图信息架构：错误信息置顶，源信息折叠在底部

Status: accepted

基于用户手绘原型图（`原型图.png`）重新设计侧边栏“错误分析视图”的信息架构：错误类型与“重新 AI 分析”同行置顶，下方为原始报错 / 中文翻译等宽双栏，关键词、错误分析、修复建议、错误分析会话依次向下；调用栈、终端输出、源代码上下文归入底部“源信息”分组并默认折叠。会话头部改为透明图标按钮（新会话、生成修复补丁、添加文件、恢复默认），发送仍是带文字的底部主操作。

选择该架构是因为用户明确希望把完整源码上下文、调用栈、终端输出等辅助信息降权，让错误识别、根因分析与修复动作保持在首屏可达；图标化会话头部避免侧栏被文字按钮占满，同时保留“生成修复补丁”作为强调操作。

Considered Options: 保留原先“源代码上下文 / 调用栈 / 终端输出”各自独立卡片铺在首屏（被否：纵向空间被辅助信息占满，首屏无法聚焦错误）；源信息三项默认展开（被否：与原型意图不符）；会话头部保留文字按钮（被否：用户原型注明使用透明底简约图标按钮）。

Consequences: `analysisWebview` 渲染顺序改为 头部（错误类型 + 原始/翻译 + 关键词）→ 错误分析 / 修复建议 / 错误分析会话 → 源信息；源信息三项默认折叠、展开状态互相独立；源代码上下文展开后按文件行展示，点击行再展开代码预览。后续新增辅助信息默认放入“源信息”分组，不直接铺在首屏。
