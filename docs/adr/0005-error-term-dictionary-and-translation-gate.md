# 报错术语词典与翻译成功门槛

Status: accepted

“核心报错术语”的 `cn` 在上一版仍完全信任 LLM 输出，同一错误类型在不同分析中可能得到不同译名，甚至出现把英文原文当中文回传的情况（如 `cn: "sqlite3"`）。为避免胶囊展示不可靠翻译，扩展端内置常见错误类型的权威译名词典，并把词典同时注入分析 Prompt。

决策：

1. 词典以“异常名（不含模块前缀）→ 中文”存储，初始覆盖 29 个 Python 内置异常以及 `ConnectionError`、`ResponseError`、`OptionalError`，共 32 条；命中词典时胶囊的 `cn` 一律使用词典值并覆盖 LLM 结果。
2. 词典同时作为参考表注入分析 Prompt，要求翻译正文与核心报错术语使用同一译名；扩展端仍做权威覆盖，双保险。
3. 未命中词典的术语，只有 `cn` 非空且小写后不同于 `en` 原文才算翻译成功，否则不进胶囊；命中词典视为必然成功。
4. 展示端（侧边栏胶囊与编辑器 Hover）再次应用词典解析，保证已缓存条目同样准确，无需再次清空缓存。

Considered Options:

- 词典只做兜底、不覆盖 LLM（被否：无法保证每次翻译准确一致）。
- 词典只放在扩展端、不进 Prompt（被否：翻译正文与胶囊译名可能不一致）。
- 只要 `cn` 非空就算翻译成功（被否：`cn` 等于英文原文时等于没翻译）。

Consequences:

- 新增或修改词典只改数据文件，不改校验逻辑。
- 未被词典收录且 LLM 无法给出有效中文的标识符（如 `sqlite3`）不会出现在胶囊中；这是“出现且翻译成功才收”规则的直接结果。
- 词典参考表使 Prompt 增加约 30 行，成本可接受。
