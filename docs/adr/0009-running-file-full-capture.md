# 运行文件全量捕获

Status: accepted

报错上下文此前对所有栈帧文件只取错误行附近的窗口（末帧 ±60 行等）并受 7000 字符总量预算约束，超预算整文件跳过；用户实际运行的入口脚本（"运行文件"，如 `python main.py` 中的 `main.py`）因此往往只看到顶部几十行，甚至因文件过大而完全缺席。现决定：运行文件在分析 prompt、修复 prompt、对话自动加载文件与 UI 中一律以完整内容呈现；识别以终端命令行解析为主、primary 栈首帧兜底（缓存查阅路径无命令行，走首帧回退）；运行文件不参与 7000/16000 字符竞争，其余文件在扣减其长度后的剩余预算内挑选，不设硬截断，仅当超过 50k 字符时在 UI 与日志标注"文件很大，可能影响分析质量"；运行文件在工作区外且不在依赖/生成目录时，其所在目录加入临时锚点，位于依赖/生成目录内则维持 project-only 排除；运行文件与报错文件同路径时占据 P0 位并以完整内容呈现，不产生重复条目。

原因：根因常常依赖入口脚本顶部的前置状态（初始化、配置读取、控制流），窗口截断会系统性丢失这些信息；入口脚本是用户意图的直接证据，应作为最高优先级上下文。

Considered Options:
- 运行文件仍受 7000 字符预算约束（被否：超过预算的文件整文件缺席，违背"全量"要求）。
- 设硬性截断上限（如 30k/50k 字符）（被否：字面要求是"全部内容"，改为软护栏标注）。
- 严格 project-only、不给工作区外的运行文件加临时锚点（被否：跨工作区跑脚本时全量捕获落空）。
- 对话层运行文件不计入总量预算（被否：总量边界不可预测，与其余消费者不一致）。

Consequences:
- ADR-0008 中"7000 字符预算内按优先级挑选"对运行文件豁免；配置文件等其余候选仍受预算约束。
- `ContextBuilder` 新增 `runningFile` 输出与命令行为主的识别入口；TerminalWatcher 需把命令行传入，缓存查阅路径无命令行，走 primary 栈首帧回退。
- 对话上下文管理器的自动文件上限对运行文件豁免（不再 7000 截断、不再因总量被跳过），其余文件在剩余预算内挑选。
- 修复补丁允许文件列表加入运行文件；UI 与 prompt 以"运行文件（完整）"标注。
