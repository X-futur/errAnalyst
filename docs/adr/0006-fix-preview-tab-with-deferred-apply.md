# 修改预览选项卡：修复确认从逐处即时写盘改为“结束修复”一次性应用

Status: accepted

侧边栏卡片里的修改预览空间局促，用户希望预览独立成选项卡且能看到完整文件。原流程每处“接受”立即写入真实文件并记录编辑位置供“撤销全部”逆操作；新流程改为：修复会话期间不写盘，所有改动集中在一个“修改预览”选项卡中展示与确认，“结束修复”时一次性把已接受修改写入真实文件并关闭预览。

“修改预览”是完整文件视图（未改动行原位保留、行号按当前虚拟文档实时计、红旧绿新标出全部改动、文件切换器集中展示所有涉及文件）；逐处确认在预览内联按钮、侧边栏卡片与编辑器 CodeLens 三处同步；“撤销全部”在会话期间为纯内存重置（文件未动，天然安全），结束修复后靠 VS Code 撤销与 git 兜底；写盘前逐文件与补丁生成时的原始快照逐字比对，被外部改动的文件跳过写入并提示。

Considered Options:
- 保持逐处即时写盘（被否：确认过程文件持续变化，无法提供稳定、可整体预览的最终形态；撤销全部需要复杂的位置追踪）。
- 预览只列改动行的压缩 diff（被否：用户要求未改动代码保持完整上下文与行号）。
- 结束修复时不做快照比对直接覆盖（被否：违背 ADR-0001 的“应用前校验”护栏，会冲掉用户等待期间的改动）。

Consequences:
- 移除现有 `applied` 位置追踪（startLine/afterLine/order）与逐处 undo 机制。
- ADR-0001 的“应用前双重校验”从逐处接受时执行改为“结束修复”时按文件执行。
- 编辑器装饰语义变为“这块将改动”：pending 与已接受保留红删除线，已拒绝无标记，写盘成功后统一清空。
- 一键修复与生成修复补丁点击即自动弹出预览选项卡（含生成中状态）；手动关闭不结束会话、不强制重弹。
