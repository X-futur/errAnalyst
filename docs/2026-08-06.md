## 二、一键修复预览的演进

1. **编辑器内“虚拟绿行”方案（不可行）**：用户希望修改处用红底标出旧代码，并在旧代码行上方新增一行绿色虚拟行展示新代码。尝试用 `TextEditorDecorationType` 的 `before`/`after` 装饰实现，但 VS Code 该 API 不支持内容换行（[microsoft/vscode#63600](https://github.com/microsoft/vscode/issues/63600)，换行符被忽略），编辑器内无法渲染真正的多行虚拟行，绿色与红色只能挤在同一行。
2. **过渡方案：卡片内红绿双行预览**：编辑器只保留红色旧行标注，侧边栏修复卡片里对每个待确认补丁渲染“绿新在上、红旧在下”的差异预览。能看但空间局促。
3. **最终方案（本次）**：经 grill-with-docs 会话重新设计为**会话级完整“修改预览”选项卡 + 延迟写盘**，实现见第四、五节。此前“每处补丁单独弹出预览选项卡”的中间版本未保留，被本方案取代。

## 三、grill-with-docs 设计会话：11 项决策

2026-08-06 通过 grill-with-docs（结合 domain-modeling）逐项确认以下共识：

| # | 决策 |
| --- | --- |
| 1 | 预览 = 完整文件视图，未改动行原位保留，行号按当前虚拟文档实时计（非压缩 diff） |
| 2 | 多文件 = 同一选项卡内顶部文件切换条，一次显示一个文件 |
| 3 | 改动渲染：未确认 = 红旧（删除线）+ 绿新双行提案；已接受 = 旧行消失、绿行保留；已拒绝 = 恢复普通文本 |
| 4 | 确认入口：预览内联按钮 + 卡片按钮 + 编辑器 CodeLens 三处实时同步 |
| 5 | 结束修复时未确认处不写入，先弹提示确认 |
| 6 | “结束修复”即原按钮，语义升级为唯一写盘动作（应用 + 关预览 + 结束会话） |
| 7 | 撤销全部只作用于会话期间（内存重置），结束后靠 VS Code 撤销 / git；移除 applied 位置追踪 |
| 8 | 写盘前逐文件与生成时快照比对，不一致的文件跳过并提示，不影响其他文件 |
| 9 | 一键修复 / 生成修复补丁点击即自动弹出（含生成中状态）；手动关闭不结束会话、不强制重弹；卡片“预览”按钮可重开 |
| 10 | 行号含 pending 双行提案的行数，确认时实时更新 |
| 11 | 编辑器装饰：pending 与已接受都保留红删除线、已拒绝无标记，写盘成功后清空 |
