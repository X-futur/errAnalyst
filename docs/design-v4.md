# ErrAnalyst 第四阶段设计文档：错误分析视图 UI 重构

> 基于 2026-08-03 grill-with-docs 会话与用户手绘原型图（`原型图.png`）产出。
> 与 [design-v3.md](./design-v3.md) 的关系：保留错误分析对话、一键修复与逐处确认能力，仅重排“错误分析视图”的信息架构与视觉呈现；正式决策见 [ADR-0003](./adr/0003-analysis-view-information-architecture.md)。

## 一、信息架构（从上到下）

1. 头部
   - 第一行：错误类型（如 `ZeroDivisionError`）与“重新 AI 分析”同行，右侧为重新分析按钮
   - 第二行：原始报错 | 中文翻译，等宽双栏，允许换行，窄侧栏下也不堆叠
   - 关键词中英对照胶囊（如有）
2. 错误分析
3. 修复建议
   - 空闲态：右下角“一键修复”
   - 激活态：原位替换为“共 N 处 · 已接受 X”、全部接受 / 全部拒绝 / 撤销全部 / 结束修复、逐处接受 / 拒绝 / 查看
4. 错误分析会话
   - 头部 4 个透明底图标按钮：新会话、生成修复补丁（强调色）、添加文件、恢复默认
   - 上下文文件 chips 横向排列、可横向滚动
   - 消息区（内部滚动）
   - 底部带文字“发送”按钮，Enter 发送、Shift+Enter 换行
5. 源信息（分组）
   - 调用栈：默认折叠
   - 终端输出：默认折叠
   - 源代码上下文：默认折叠；展开后先显示文件行（文件名 + 路径 + 行范围，主报错文件加强调色），点击行展开 / 收起代码预览

## 二、视觉与行为规则

- 沿用 VS Code 原生主题变量（`--vscode-sideBar-background`、`--vscode-focusBorder`、`--vscode-panel-border` 等），不引入品牌色大背景或渐变装饰
- 整体不使用卡片式容器；模块之间以 1px 分隔线隔开，错误类型、类别标签、消息气泡等均改为扁平文本/左侧色线，仅按钮、关键词胶囊、文件 chips 保留细边框
- 基础字号从 12px 调小至 11px，代码与辅助信息 10-11px
- 错误类别、关键词、修复与发送等关键操作保留现有强调色
- 缓存查阅态保留“来自本地缓存”徽标，不再有独立工具栏

## 三、实现位置

- `src/ui/analysisWebview.ts`：渲染顺序、头部、源信息分组、会话图标按钮、主题变量与样式
- 消息协议、修复会话、对话上下文逻辑不变

## 四、实现顺序

1. 头部与信息架构重排
2. 源信息分组与文件行展开
3. 会话头部图标按钮与 chips 横向滚动
4. 原生主题变量与字号微调
5. 文档与 ADR 收尾
