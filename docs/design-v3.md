# ErrAnalyst 第三阶段设计文档：错误分析对话

> 基于 2026-08-02 grill-with-docs 会话产出。
> 与 [design-v2.md](./design-v2.md) 的关系：保留一键修复与逐处确认流程，新增“错误分析对话”作为问答和基于会话生成补丁的入口；正式决策见 [ADR-0002](./adr/0002-error-analysis-chat.md)，术语见 [CONTEXT.md](../CONTEXT.md)。

## 一、目标与非目标

**目标**：

- 修复建议更详细：同一次 AI 分析返回的 `fixSuggestion` 必须点名问题文件、给出 `文件:行号` 引用和分步操作，前端把行号渲染为可点击链接。
- 修复建议卡片下方常驻“错误分析对话”：解释根因、回答追问。
- 对话可基于对话上下文与会话历史生成修复补丁，复用现有逐处确认与撤销流程。
- 对话上下文自动加载分析 user prompt 中的文件，支持用户新增、移除与恢复默认。
- 外部问题或无法确定时只给操作建议，不编造代码结论或行号。

**非目标**：

- 第一版不做流式输出、不做历史摘要压缩、不持久化对话历史。
- 对话本身不直接修改文件；所有代码修改仍通过修复会话逐处确认。
- 不自动重跑终端命令，不自动重新 AI 分析。

## 二、UI 与交互

- “错误分析对话”卡片位于修复建议卡片下方，常驻显示：顶部上下文文件 chips，中间内部滚动消息区，底部输入框。
- 卡片右上角两个入口：“新开会话”“生成修复补丁”。
- 上下文文件 chips 可单独移除；“恢复默认”一键回到该报错自动加载的文件集。
- AI 回复用安全 Markdown 子集渲染（标题、加粗、有序/无序列表、行内代码、围栏代码块），`文件:行号` 可点击，其余 HTML 一律转义。
- 补丁生成结果复用现有修复会话 UI（编辑器绿/红、CodeLens、侧边栏汇总）；外部问题/无法确定时，把 AI 的文字原因作为一条对话消息展示。

## 三、对话上下文

- **自动加载**：分析 user prompt 中 Source Context 的文件，保存“路径 + 行范围”；每次发送前重读当前文件内容，内容相比分析时变化则在对话中提示“该文件已变化”。
- **用户新增**：系统文件选择器多选，仅接受文本文件；单文件最多 7000 字符，对话上下文总预算 16000 字符，超出截断并在 chips 上标注“已截断”。
- **移除**：任何文件（含自动加载的）都可单独移除；移除后不再发送给 AI，也不再进入补丁白名单。

## 四、每轮 AI 输入

```
原始 Traceback
+ Parsed Error Data
+ 最新分析结果（translation / analysis / fixSuggestion，重新分析后自动更新）
+ 对话上下文文件
+ 会话历史（受历史上限约束）
+ 当前问题
```

## 五、行为规则

- **不确定 / 外部问题**：对话明确说明“无法确定”或“这不是代码内问题”，只给操作步骤（查哪个配置、看哪个服务、如何验证）；生成修复补丁时返回空 `changes[]` 并附文字原因。
- **历史上限**：保留最近 20 条或 N 字符，超出丢弃最早消息并提示“更早消息已截断”；补丁生成使用同一份受上限约束的历史。历史摘要压缩列为后续增强。
- **配置开关**：新增 `errAnalyst.enableChat`，默认 `true`；关闭时对话卡片不显示。

## 六、补丁生成

- 点击“生成修复补丁”后，把当前会话历史并入补丁 Prompt，复用 `buildFixPrompts` / `parseFixResponse` 管线。
- 白名单为当前对话上下文中的所有文件（自动加载 + 用户新增，移除后失效），不再局限于分析时 Source Context。
- 校验与落盘完全复用 `FixSessionManager`：展示前、应用前双重校验，逐处接受/拒绝，支持全部接受/拒绝与撤销全部。
- 空结果时复用“AI 未生成可应用的修复补丁”提示，并展示 AI 返回的文字原因。

## 七、生命周期

- 对话会话绑定当前报错：遇到新报错或切换缓存条目时自动新开会话；同一报错点击“重新 AI 分析”保留历史，只更新附着的最新分析结果。
- “新开会话”清空消息历史并结束修复会话，保留对话上下文文件；点击前弹确认。
- 对话历史不落盘，不进入本地缓存。

## 八、建议文件结构

```
src/chat/
├── types.ts              ← ChatMessage、ChatSession、对话上下文文件类型
├── prompt.ts             ← 对话 Prompt 构建（每轮输入组装 + 行为规则）
├── session.ts            ← 对话会话管理（新开会话、历史上限）
└── contextFiles.ts       ← 自动加载/新增/移除/恢复默认 + 预算与二进制校验
```

- `src/llmProvider/types.ts`：`LlmProvider` 增加多轮对话接口，参数预留流式扩展位。
- `src/ui/analysisWebview.ts`：新增对话卡片 HTML/CSS、Markdown 白名单渲染、chips 与输入框消息处理。
- `src/extension.ts`：组装 `ChatSessionManager` 与现有 `ContextBuilder`、`FixSessionManager`、LLM Provider。
- `src/llmProvider/openaiCompatible.ts`：修复建议 Prompt 增加“点名问题文件 + 文件:行号 + 分步操作”约束。

## 九、实现顺序

1. LLM Provider 多轮接口 + `chat/types.ts`、`chat/prompt.ts`、`chat/session.ts`（单测：历史截断、上下文预算、外部问题规则）
2. `chat/contextFiles.ts`（单测：新增/移除/恢复默认、预算截断、二进制拒绝）
3. Webview 对话卡片（Markdown 渲染、chips、输入、新开会话）
4. 生成修复补丁接线（会话历史入 Prompt、白名单扩展、空结果原因展示）
5. `errAnalyst.enableChat` 配置、修复建议行号链接、文档收尾
