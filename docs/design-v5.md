# ErrAnalyst 第五阶段设计文档：修改预览选项卡与延迟写盘

> 基于 2026-08-06 grill-with-docs 会话产出。
> 与 [design-v4.md](./design-v4.md) 的关系：保留错误分析视图信息架构，把“一键修复 / 生成修复补丁”的确认流程从侧边栏卡片即时写盘改为独立“修改预览”选项卡 + “结束修复”一次性应用；正式决策见 [ADR-0006](./adr/0006-fix-preview-tab-with-deferred-apply.md)，术语见 [CONTEXT.md](../CONTEXT.md)。

## 一、修改预览选项卡

- 自动弹出：点击“一键修复”或对话“生成修复补丁”的瞬间弹出，先显示“正在生成修复补丁…”，就绪后原地渲染；手动关闭选项卡不结束会话，也不强制重弹；需要时点卡片“预览”按钮重新打开。
- 形态：完整文件视图（非压缩 diff），未改动行原位保留；行号 = 当前虚拟文档实际行号（pending 双行提案两行都计入），确认时实时更新。
- 多文件：同一选项卡内顶部文件切换条（文件名 + 改动数），一次完整显示一个文件的最终内容。
- 改动渲染：
  - 未确认（pending）：红色旧行（删除线）在上、绿色新行在下，双行提案；
  - 已接受：旧行消失、绿行作为最终内容保留，底色保持到结束修复；
  - 已拒绝：新行消失、恢复普通文本。
- 逐处确认：预览内联“接受/拒绝”按钮 + 卡片按钮 + 编辑器 CodeLens 三处实时同步；每个提案旁显示修改原因。

## 二、确认与写盘

- 会话期间不写盘；“撤销全部”= 纯内存重置为待确认；结束修复后不再提供撤销，靠 VS Code 撤销 / git 兜底。
- “结束修复”是唯一写盘动作：若还有未确认处先提示“将不写入”，应用已接受修改、关闭预览、结束会话。
- 写盘前逐文件与补丁生成时的原始快照逐字比对：一致则写入，不一致则跳过该文件并提示“已被外部修改，本次未写入”；单个文件失败不影响其他文件。
- 编辑器装饰：pending 与已接受保留红删除线（文件确实还没改），已拒绝无标记；写盘成功后统一清空。

## 三、实现位置

- `src/ui/fixPreviewPanel.ts`：扩展为完整预览（文件切换器 + 虚拟文档渲染 + 双行提案 + 内联确认 + 结束修复按钮）。
- `src/fix/session.ts`：会话持有每文件原始快照与虚拟文档状态（pending/accepted/rejected）；移除 `applied` 位置追踪；refresh 不再写盘。
- `src/fix/decoration.ts`：装饰按状态渲染（pending/accepted 红、rejected 无）。
- `src/ui/analysisWebview.ts`：卡片保留汇总操作与逐处按钮、移除内联预览。
- `src/extension.ts`：消息路由新增预览/结束修复处理；生成补丁时自动弹出预览。

## 四、实现顺序

1. 会话模型：文件快照 + 虚拟文档 + 状态机（accept/reject/reset/apply）
2. 预览选项卡渲染（文件切换、双行提案、行号、内联确认）
3. 三处同步与自动弹出
4. 结束修复写盘与逐文件校验
5. 文档与 ADR 收尾
